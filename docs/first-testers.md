# Protocol for initial testers

Goal: check whether a researcher without programming experience can follow the guide without editing source files.

Recruit volunteers openly, including through Reddit, each on **their own instance**. Do not invite them as GitHub collaborators. A public repository gives them access to the guide without write permission. See [the open-beta protocol](open-beta.md). Use a library or a few references whose content may be sent to ChatGPT. The maintainer collects no key or password.

| Stage | Expected success | Record |
|---|---|---|
| Installation | Render service Live and all four fields understood | Approximate time, confusing terms or screens |
| Authentication | One click after the password returns to ChatGPT | Browser/application and any error message |
| Reading | Known collections or item found | Agreement with Zotero Web |
| Duplicates | Known reference recognized without creation | DOI, then title/author; ambiguities preserved |
| Controlled write | One note added and read back | No other changes |
| Routine use | Tags/collection added without removing existing ones | Test only on authorized items |
| Mobile | Same read possible in the usual application | Product, OS and ability to select the MCP |
| Reconnection | Expiry handled and new connection successful | Difficulty and number of manual steps |

Do not claim “all mobile devices” support from the developer's browser alone. Publishing the code does not fix a product's lack of MCP availability.

## Feedback to send

- Technical confidence: beginner / intermediate / advanced.
- Step reached and expected/actual result.
- ChatGPT app, browser and operating system.
- Exact error text after removing personal information.
- Actions you would have preferred to avoid.

A test passes when the person completes reading plus one controlled write, understands how to disable writes and knows how to revoke the key. The validation note remains in their library: no deletion tool will be added for this test.
